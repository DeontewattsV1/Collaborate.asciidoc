# Repository-wide AI agent session — experimental v1

**Hub:** [Issue #34](https://github.com/DeontewattsV1/Collaborate.asciidoc/issues/34). **Source of authority:** authenticated GitHub API account IDs and the protected default-branch `.github/session-principals.json`; no shared API keys or model-label assertions are treated as identity. **State:** the repository's `agent-collaboration` Actions reconciliation is active on protected `main`; membership still requires an explicit, valid GitHub-authenticated account join and is not proof of model/provider identity.

## Join, heartbeat, leave, rejoin

An authorized GitHub App or authenticated account posts an event beginning with **one standalone command line** as a new comment on issue #34:

```text
Collaborate-Session: {"v":1,"action":"join","instance":"run-001","role":"claude-code","pr":30}
```

Some AI integrations automatically append a Markdown attribution footer. The parser also accepts a **strictly bounded footer** consisting only of a blank line, `---`, and `_Generated by [Tool Name](https://provider.example/path)_` with short, restricted characters and an HTTPS link. This is inert, self-reported text, **not model authentication**. Additional prose or prompt content still invalidates the comment. Edited session events remain rejected.

For a long-running session, post a fresh comment with the same `instance`, `action:"heartbeat"` at least hourly. A heartbeat refreshes only liveness: it **must not change** the `role`, `pr`, or `head` asserted by the latest `join`. If a heartbeat or leave explicitly names a different role from that join, the event is ignored; omitting the role is allowed. This protects against accidental cross-agent activity on shared accounts, but a matching self-reported role is **not** proof of model identity. Send a new `join` to update the current session's claims. To end, use `action:"leave"`. After a restart or expiry, **post a new `join` event** using the same instance ID (or a new ID). A join within an active two-hour episode retains that episode's start; a join after `leave` or expiry begins a fresh episode with a fresh start time. Do not edit a previous event; edited events are ignored. Comment deletion is not an immutable audit trail.

If a `join` omits `role`, it is displayed as `unknown` rather than crashing reconciliation. An asserted `pr` and 40-character `head` are checked against the current open PR list; the hub distinguishes a matching head, a stale/mismatched head, and a PR that is not open. A matching SHA does **not** verify the author's identity, passing Actions checks, or reviewer approval.

`role`, `instance`, `pr`, and optional `head` are **claims**. Identity is the GitHub API account's immutable numeric ID, current login and account type, checked against the trusted policy. A shared human account is verified only as the human account, **not** as the Claude, Manus, Codex or other model using it. Separate, correctly authorized GitHub App identities are the strongest supported binding here, but still do not cryptographically prove which model generated a particular response. Authenticate providers at their own issuer to obtain stronger model/session attestations; do not claim that v1 does that.

## Synchronization and handoffs

The active provider-neutral `agent-collaboration` workflow receives GitHub comments, PR events, review events and manual dispatches; a 15-minute schedule reconciles missed events and expires stale sessions. The workflow reads only the trusted default branch, never executes a PR's code or untrusted comment text, and uses the ephemeral GitHub Actions token to update a **single** GitHub Actions-authored summary comment in issue #34. Any GitHub-connected agent can request to join; only principals in the verified GitHub-account policy become active. No `ANTHROPIC_API_KEY` or other model-provider API key is needed for coordination. Provider-specific model execution is a separate, explicitly authorized integration. It is not always-on or real-time; Actions delivery and schedules can be delayed.

The hub includes active GitHub principal and self-reported role, last event, linked PR and asserted head, open PR head SHAs, and a SHA-256 digest of the accepted event snapshot. The digest is **not** a tamper-proof, append-only journal. All changes, tests, `go-verify`, actual checks, review threads and merge eligibility must be independently verified on the linked PR. PR-level leases remain governed by the existing `collaborate-coordination` workflow. A worker must inspect current leases before modifying code.

Handoffs must name the exact PR, commit SHA, changed paths, commands actually run, PASS/FAIL/NOT RUN results, unresolved review findings and next decisive test. A second agent may challenge the evidence but cannot substitute for human approval when required.

## Security and lifecycle

- Only exact GitHub account ID + login + type in `.github/session-principals.json` can become an *active session principal*. Unknown join requests are recorded as unrecognized, not enrolled. Observing a bot elsewhere does not automatically authorize it.
- A heartbeat does not revive an expired session. A new `join` is required after leave or expiry. An active instance expires two hours after its most recent accepted event. Sessions are keyed by `(GitHub principal ID, instance ID)` to prevent cross-account takeover of an instance name.
- Join events do not create GitHub access, grant runtime tools, bypass reviewer requirements, merge anything, trigger paid models, or manage secrets. This is an authenticated **GitHub-principal** session protocol, **not** fully authenticated AI-provider identities.
- The public hub must contain no credentials, protected unpublished research, customer data or private logs. An external model must be separately connected and authorized to post GitHub comments under its identity.
- No live ruleset, required CI, branch protection or existing PR is altered by the session workflow. Never use a green session check to infer a passing `go-verify` or valid independent review.
