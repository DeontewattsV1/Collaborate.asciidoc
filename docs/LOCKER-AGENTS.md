# Git Locker assistant agents

The [Git Locker Index](../agents/locker/GIT-LOCKER-INDEX.md) lists 1,000 repo seeds. Each seed is also a **runnable assistant agent** whose job is to help a more capable *primary* AI model do better work. All of them use the same API keys and GitHub Environments as the model bridge.

## What each agent has

Every agent is one line in `agents/locker/index.json`, generated by `python3 scripts/locker_agents.py index --write`:

| Field | Example (`#9 lattice-agent-orchestrator`) |
|---|---|
| Identity | Number, name, domain, concept and MVP, all from the index |
| Role and job | *Orchestrator*: splits a complex task into subtasks, delegates them to other assistants and merges their results, viewed through its domain lens |
| Own workflow | `redact-input → tool:route → brief → delegate (bounded) → synthesize → receipt` |
| Tool | A deterministic local helper, where one fits: `route`, `risk`, `redact`, `normalize`, `keywords`, or a `ledger`/`receipt`/`snapshot` anchor |
| Delegation | Only the 100 coordinators (orchestrator, switchboard, mesh, mixer and loom in every domain) may delegate |

Each agent combines two things:

- **Its archetype (one of 50)** sets the assistant job, for example *Standards checker*, *Intent compiler*, *Scenario tester*, *Guardian*, *Privacy guard*, *Decision scorer* or *Calibrator*.
- **Its domain (one of 20)** sets the lens it works through. For example, `blueprint-cyber-guardian` reviews through a cyber-resilience lens, and `humane-access-compass` scores options through an accessibility lens.

## How they help a bigger model

**`assist`** works in four steps:

1. A deterministic router picks a team of complementary specialists for the task, with one agent per role.
2. Each specialist writes a short brief: requirements, risks, edge cases, a plan or evidence.
3. The **primary model** answers the task using those briefs. It is told to treat them as advice to verify, not as instructions.
4. A **guardian** from the most relevant domain reviews the answer.

**`run`** executes a single agent. When that agent is a coordinator, it can delegate recursively: it writes `DELEGATE: <agent> :: <subtask>`, the runtime runs the child agent, and the coordinator merges what comes back. Children that are coordinators can delegate further.

## Bounded and auditable

| Limit or guard | How it works |
|---|---|
| Recursion | Stops at `--max-depth` (at most 3). Self-delegation, cycles back to an ancestor, and unknown agents are refused and logged. |
| Model calls | Stops at `--max-calls` for the whole run (at most 40); work left over is reported as `NOT RUN`. |
| Secrets | Redacted from the task, from every prompt, from every model output and from every trace record. |
| Side effects | None. Agents have no shell, file or network tools: they only call the selected model API. They advise; they never push, merge or deploy. |
| Audit trail | Every step goes into a hash-chained trace (`--out trace.json`). Each record links to the previous record's hash. |

Tests in `tests/test_locker_agents.py` cover each of these. Removing any one guard makes at least one test fail; each was checked by disabling it.

## Use it

```bash
python3 scripts/locker_agents.py list --domain cyber            # browse; also --archetype guardian, --search
python3 scripts/locker_agents.py show 658                       # one agent's full spec
python3 scripts/locker_agents.py route --task "..."             # which team would be picked

# offline (no keys)
python3 scripts/locker_agents.py assist --task "harden our CI against secret leaks"
python3 scripts/locker_agents.py run lattice-agent-orchestrator --task "..." --out trace.json

# live: set MODEL_API_KEY and MODEL_NAME (optionally ASSISTANT_MODEL_NAME for a cheaper assistant model)
python3 scripts/locker_agents.py assist --provider anthropic --task "..." --assistants 4
```

**On GitHub:** go to **Actions → locker-agents → Run workflow**, then choose the mode, task and provider.

- The run uses the `agent-<provider>` environment created by `scripts/setup_github_environments.sh`.
- You can add an `ASSISTANT_MODEL_NAME` variable to that environment to run assistants on a cheaper model while the primary model stays on `MODEL_NAME`.
- Choose provider `mock` to try it without keys.
- If a provider has no key yet, the run finishes green with a "not configured" warning.
- Each run uploads its trace as an artifact and writes a summary that shows the delegation tree, the answer and the review.

## Limits, stated plainly

- Agent outputs are **model-generated and UNVERIFIED**. The review step reduces mistakes; it does not prove correctness.
- "Recursive" means bounded delegation between agents within one run. Agents do not run continuously, and they do not modify themselves or the repository.
- The 1,000 specs are generated from 50 archetypes × 20 domains, so agents in the same archetype share a job template and differ by domain lens and name. Change the behaviour by editing `ARCHETYPES` or `DOMAINS` in `scripts/locker_agents.py` and regenerating. A test fails if the committed index goes stale.
