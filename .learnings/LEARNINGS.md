## [LRN-20261123-003] knowledge_gap

**Logged**: 2026-11-24T21:00:00Z · **Priority**: high · **Status**: resolved · **Area**: backend

### Summary
Reasoning models count hidden reasoning tokens against the output limit, so a small limit can return an empty answer.

### Details
At `max_completion_tokens` / `maxOutputTokens` = 1100, OpenAI or Gemini could spend the entire budget on reasoning. The bridge then failed with the misleading error "no supported text output".

### Suggested Action
Use a generous token budget (8192), ask for a short answer in the prompt instead, and report `finish_reason=length` / `MAX_TOKENS` explicitly.

### Metadata
- Related Files: scripts/agent_model_bridge.py

### Resolution
- **Resolved**: 2026-11-23 · **Commit/PR**: #67

## [LRN-20261124-001] best_practice

**Logged**: 2026-11-24T21:00:00Z · **Priority**: high · **Status**: promoted · **Area**: infra

### Summary
A PR cannot fix the policy that its own `pull_request_target` check reads from trusted `main`.

### Details
`agent-registry` reads `.github/agent-registry.json` from the base branch, by design, so that a PR cannot authorize itself. A PR that repairs a broken registry therefore fails that check until a maintainer merges it.

### Suggested Action
When a required check reads policy from `main`, say so once on the PR and hand the merge to the maintainer. Do not try to make the check pass from inside the PR.

### Metadata
- See Also: ERR-20261124-002 · **Promoted**: AGENTS.md

## [LRN-20261123-004] best_practice

**Logged**: 2026-11-24T21:00:00Z · **Priority**: medium · **Status**: promoted · **Area**: tests

### Summary
A scripted edit whose anchor did not match left the file unchanged, and "all tests pass" was briefly misread as "the new tests pass".

### Details
A Python `str.replace` insertion of new tests found no anchor and inserted nothing, so the suite still passed. Mutation checks (disable a guard, expect a failure) and `grep` for the new test names caught it.

### Suggested Action
After a scripted edit, assert that the anchor matched exactly once, and confirm that a new test fails before the fix and passes after it.

### Metadata
- Pattern-Key: verify.tests_actually_ran · Recurrence-Count: 2 · **Promoted**: AGENTS.md

## [LRN-20261123-005] best_practice

**Logged**: 2026-11-24T21:00:00Z · **Priority**: medium · **Status**: promoted · **Area**: config

### Summary
Before creating a PR, check the open PRs: the maintainer may already have opened one from your branch, or an earlier PR may hold the lease on your paths.

### Details
- PR #64 had been opened by the maintainer from the agent's branch, so the agent updated it instead of opening a duplicate.
- #63 held the lease on `README.md`, so the agent removed that path from its own PR.
- A force-push to replace a merged branch was blocked; pushing a fresh branch name worked.

### Suggested Action
List open PRs and their files first. Never force-push to replace a branch; use a new branch.

## [LRN-20261124-002] best_practice

**Logged**: 2026-11-24T21:00:00Z · **Priority**: medium · **Status**: pending · **Area**: infra

### Summary
Workflows that need a key nobody has set up should finish green with a "not configured" warning. Real failures must still fail.

### Details
Manual runs without keys turned the Actions page red and hid genuine failures. Each workflow now has a configuration check that writes a warning and a job summary and skips its paid steps. Failing tests, invalid input and provider errors still fail.

### Suggested Action
Apply the same pattern to any new workflow that depends on a credential.

### Metadata
- Related Files: .github/workflows/opensandbox-sandbox.yml, .github/workflows/render-sandbox.yml, .github/workflows/agent-model-bridge.yml
